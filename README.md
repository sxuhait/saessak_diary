# 새싹일기 (saessak_diary)

## 프로젝트 소개

- 지역아동센터 멘토(대학생 멘토·봉사자)를 위한 멘토링 코파일럿 웹앱입니다.
- 누적된 수업 일지·출석 데이터를 바탕으로 아동별 학습 취약점과 다음 지도 방향을 드러내는 것이 목표입니다. 현재는 규칙 기반 진단으로 이를 제공하고 있고, 그 위에 얹을 AI 분석은 아직 준비 중입니다.

## 해결하려는 문제

- 멘토가 여러 아이를 담당하며 회차별 변화를 스스로 추적하기 어렵습니다.
- 학습 취약점 파악이 멘토 개인의 기억·감에 의존하게 됩니다.
- 출석/스케줄 관리가 따로 안 돼 결석 반복이나 방치된 과목을 놓치기 쉽습니다.
- 멘토·봉사자가 계속 바뀌는 구조라, 담당제보다는 전체가 명단을 공유하고 인수인계 없이도 아무나 이어서 기록할 수 있어야 합니다.

## 주요 기능

**계정 / 권한**
- 이메일 회원가입(Supabase Auth) + 로그인. 가입 시 멘토/봉사자 역할을 직접 선택하고(관리자는 가입 화면에서 선택 불가), 이후 화면·기능은 역할과 무관하게 동일합니다.
- 봉사자 계정은 마지막 활동(일지·출석 작성) 후 30일이 지나면 자동 만료됩니다 — 로그인 시점, 모든 페이지 접근(미들웨어), DB 조회/쓰기(RLS) 세 군데에서 각각 막아 우회할 수 없게 했습니다. 관리자 지정과 봉사자 재활성화는 아직 UI가 없어 SQL로 처리합니다.

**멘티 관리**
- 담당제 없이 전체 멘티 명단을 모든 로그인 사용자가 함께 보고 기록합니다(공용 명단).
- 멘티별 수업 일지 작성(날짜·과목·진도·내용), 월간 달력, 과목별 학습 현황 표, 전체 일지 이력(작성한 멘토 표시).
- 출석 체크(출석/결석/지각/사유결석 + 사유) 전용 월간 달력.
- 규칙 기반 학습 진단: 외부 AI/API 없이 날짜 차이·횟수·비율 계산만으로 방치된 과목, 최근 학습 공백, 결석/지각 패턴(특정 요일 쏠림 포함), 과목 편중을 감지해 경고합니다.

**센터 운영**
- 센터 공용 행사 달력(견학·캠프·기타). 행사별로 사진을 여러 장 올리고 갤러리로 보여주며 개별 삭제도 가능합니다(Supabase Storage `event-photos` 버킷).
- 행사 상세 일정은 "시간 + 내용" 항목을 자유롭게 추가/삭제하는 형태로 입력하고, 저장 시 시간순으로 자동 정렬되어 시간표처럼 표시됩니다.
- 요일별 수업(외부 강사) 관리 + 멘티 수강 등록 + 이번 주 휴강 처리. 새 수업 추가·수정·삭제는 관리자만 가능합니다.
- 센터 주간 시간표 보기(현재는 고정 템플릿, 표시 전용).
- "오늘 누가 오나요": 멘토는 자기 출근 요일·시간대를 등록해두고, 봉사자는 "오늘 참석합니다" 버튼으로 당일 참석을 직접 체크합니다. 오늘 출근하는 멘토(시간대 포함)와 오늘 참석 체크한 봉사자 명단은 역할과 무관하게 모두가 볼 수 있습니다.

**마이페이지 / 알림**
- 상단 네비게이션 + 새싹 그린 파스텔 톤으로 전체 디자인 통일(다크 모드 없음).
- 마이페이지: 프로필(이름) 수정, 전체 멘티 수, 챙길 멘티 알림(최근 학습 공백·출석 문제), 내가 최근 작성한 일지, 로그아웃.
- 상단 알림 벨: 챙길 멘티 진단 결과, 일주일 내 예정된 센터 행사, 본인의 봉사 만료 임박(7일 이내)을 모아서 보여줍니다.

## 기술 스택

- [Next.js](https://nextjs.org/) (App Router, Server Actions), TypeScript, React
- Tailwind CSS v4
- [Supabase](https://supabase.com/) — Postgres, Auth, Row Level Security, Storage
- [react-day-picker](https://daypicker.dev/) (달력 UI), [lucide-react](https://lucide.dev/) (아이콘)
- [Vercel](https://vercel.com/)에 배포

## 시작하기 (로컬 실행)

1. `.env.local` 파일을 만들고 아래 값을 채워주세요 (`.env.example` 참고, Supabase 프로젝트 설정 → API에서 확인):

   ```
   NEXT_PUBLIC_SUPABASE_URL=
   NEXT_PUBLIC_SUPABASE_ANON_KEY=
   ```

2. 의존성 설치 후 개발 서버 실행:

   ```bash
   npm install
   npm run dev
   ```

3. 브라우저에서 [http://localhost:3000](http://localhost:3000) 접속

이 저장소는 실제로 호스팅되는 Supabase 프로젝트(Postgres + Auth + Storage)에 연결되어 동작합니다. 스키마는 `supabase/migrations/`에 마이그레이션으로 관리되며, 로컬에 별도의 DB를 띄우지 않아도 위 두 값만 있으면 개발 서버가 그 프로젝트를 그대로 사용합니다.

아키텍처, 데이터 모델, RLS 구조, 라우트 구조 등 더 자세한 내용은 `CLAUDE.md`를 참고하세요.
